Лаборатория, одна RTX 4090. Остальные пять карт этот декодер не ускоряют.

Не качать папку Datasets из CheMLT-F: это Git LFS, около 6 ГБ, для эксперимента не нужно.
Не выкладывать этот клон на github.com/vmun/CheMLT-F: это чужой репозиторий.

Взять с ноутбука папку e0_baseline целиком и Pre-Training/PubchemModelDeberta
(энкодер, около 182 МБ). В e0_baseline уже есть:
- код
- USPTO train, val и закрытый test
- decoder_pubchem.pt: декодер после короткого PubChem, до USPTO
- отчёты 6.4% и 8.9%

На машине в лаборатории:

1. Поставить зависимости: torch, transformers, rdkit, pandas.
2. Проверить, сколько весит выгрузка ORD, и только потом качать.
3. Привести ORD к data/ord.jsonl. Каждая строка: {"product": "...", "reactants": "..."}.
   Реагенты через точку, канонический SMILES со стереохимией, как в train.jsonl.
4. Из папки e0_baseline:
   $env:HF_HUB_OFFLINE = '1'
   $env:E0_BATCH = '32'
   python train_ord.py
   Скрипт сам ничего не скачивает. Одна эпоха ORD, затем 3 эпохи USPTO train.
   Тест не читается. Если не влезает в память, E0_BATCH=16.
5. Потом оценка, тест открывается только здесь:
   python score_e0.py checkpoints\decoder_ord_uspto.pt e0_ord_report.json
6. Сравнить с уже посчитанным: без PubChem 6.4% (321/5004, 46% битый SMILES),
   после короткого PubChem 8.9% (443/5004, 38% битый SMILES).

Полные 58 миллионов PubChem заново не гонять: короткая выборка уже показала,
что декодер пишет SMILES лучше, а прирост на тесте маленький.
